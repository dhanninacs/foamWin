01

The port

A port,
not a wrapper.

FoamWin is Foundation OpenFOAM 14, cross-compiled with MinGW-w64 GCC and given a Windows operating-system layer derived from blueCFD. The result is a set of ordinary Windows executables and DLLs — not a container, not a headless Linux box in a folder.

Because it is a real build, it behaves like one. Case dictionaries are the ones you already write. Executable names, package filenames and the OpenFOAM namespace are untouched, so tutorials, scripts and habit all carry over.

Build vs. run

Compiling from source still wants a case-sensitive Linux filesystem and a MinGW-w64 cross toolchain. That is a maintainer's problem, solved once. Running it is a Windows problem, and that is solved too.

02

Pipeline

Five moves,
install to cavity.

Every step below is exercised by the package’s own smoke tests on a clean Windows machine.

  1. 01

    Download

    Take OF14-win-setup.exe for a guided install with shortcuts and an uninstaller, or the portable OF14-win.zip. Verify against SHA256SUMS.txt.

  2. 02

    Launch

    Open the OpenFOAM 14 shortcut, or double-click of14-shell.bat. The launcher wires the binaries and DLLs, then drops you in your run directory.

  3. 03

    Mesh

    blockMesh for the structured core, snappyHexMesh for geometry, and cfMesh — cartesian, tet, poly and 2D meshers with boundary layers.

  4. 04

    Solve

    Legacy solvers such as icoFoam and the modern foamRun framework. Serial by default, or local parallel with optional Microsoft MPI.

  5. 05

    Look at it

    The smoke test writes cavity.foam. Open it in ParaView, or export with foamToVTK and post-process with foamPostProcess.

PowerShell · FoamWin 14
# from the extracted package
. ./of14-shell.ps1 -Quiet
# everything is now on PATH, as on Linux
blockMesh -help

# the full smoke test: mesh, check, solve, verify
./of14-smoke-test.ps1

# four processes, if Microsoft MPI is installed
./of14-smoke-test.ps1 -Processes 4

Paths containing spaces are handled by a temporary junction alias, so C:\Program Files\FoamWin and D:\my cases both work without renaming anything.

04

Evidence

Tested where it
actually runs.

Not on a Linux CI box wearing a Windows costume. On Windows, from the installed package, through the Desktop shortcut.

  • Startup every packaged executable answers -help
  • Cavity legacy icoFoam case through 0.5 s, Mesh OK
  • Modern incompressibleFluid cavity with foamRun, to time 10
  • Decompose Scotch and METIS, serial and parallel
  • Redistribute PT-Scotch and Zoltan under MS-MPI
  • cfMesh cartesianMesh with boundary layers, passing checkMesh
  • Install setup, shortcut, uninstall, and re-run from the installed tree
  • Paths spaces in install and case directories, runtime DLL imports, ZIP integrity
  • Engine feature extraction, velocity post-processing and VTK export

These are execution and smoke tests — proof that the machinery turns and the numbers land where they should. They are not exhaustive physical-model benchmarks, and this site will not pretend otherwise.

05

Limits

What it
won’t do.

64-bit Windows only. Double precision, 32-bit labels — the combination that was built and tested.

No bundled viewer. Install ParaView yourself and open cavity.foam. Exporting VTK is built in.

Runtime compilation needs setup. Function-object code that compiles at run time wants an extra compiler configuration. Prebuilt libraries are unaffected.

Local parallel only. Multi-host runs and performance scaling under MS-MPI have not been measured.

06

Builders

An engine with
a socket.

A Windows host application does not have to speak Bash to drive OpenFOAM. of14-env.ps1 hands back a JSON document — schema version, flavour, absolute tool paths, a prepared environment, library names, MPI availability, and a normalised case directory.

Run it as an argument list, parse the JSON, use the paths. It exits with status 2 and a diagnostic if a required tool is missing, so a host adapter fails loudly instead of silently solving nothing.

Attachment guide

First consumer

Stokes — a desktop CFD workbench — drives this engine directly. It uses the JSON handshake, then runs meshers and solvers as native Windows subprocesses.

Same engine · a window on top

FoamWin is the engine.
Stokes is the workbench.

Import a STEP file, pick faces for boundaries, mesh it, run it and read the results in one window — on Windows and Linux. FoamWin supplies the native OpenFOAM 14 runtime underneath.
